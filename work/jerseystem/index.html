Project Summary

Design direction that could survive change.

I joined JerseySTEM through Catchafire as a volunteer during an active website refresh. The existing website was outdated, lacked a cohesive visual direction, and needed to be modernized under an aggressive timeline.

Using my background in UI engineering, Figma, responsive design, and WordPress, I proposed multiple homepage concepts. The second direction was selected by the team. I learned Elementor while actively developing the project, extended it with frontend code when necessary, and took increasing ownership of page development and reusable structures as the work progressed.

The Challenge

An outdated website. An evolving project. A tight deadline.

JerseySTEM needed more than a visual refresh. The website contained outdated content, inconsistent presentation, unclear page organization, and sections whose purpose was still being evaluated. Meanwhile, requirements, content, and responsibilities continued to evolve against an aggressive launch timeline.

How do you create a modern and consistent digital experience while the content, requirements, and project itself are still changing?
  • Outdated website
  • Aggressive timeline
  • Changing requirements
  • 100+ Jira tickets
  • Existing WordPress infrastructure
  • Content dependencies
  • Team transitions
  • Mobile-heavy audience
Establishing a New Direction

Designing Before Developing

Rather than immediately rebuilding the existing site inside WordPress, I used Figma to explore what a refreshed JerseySTEM experience could become. The concepts focused on hierarchy, calls to action, readability, modern imagery, and a consistent visual system. Stakeholders selected the second direction as the production foundation.

View design progression
Full Figma Direction

Seeing the Experience as One Connected System

The complete Figma direction brought the refreshed hierarchy, content rhythm, calls to action, imagery, and reusable visual patterns into one continuous homepage experience before production development began.

From Figma to Production

Turning the Design Into a Working System

Elementor was new to me when I joined. I applied my existing frontend and responsive-design knowledge while learning the tool during active development. Where the visual editor could not reproduce the intended experience on its own, I extended the implementation with custom CSS, HTML, and JavaScript.

Building for Reuse

One System. Nine Programs.

Rather than treating every STEM curriculum area as an independent page, I developed a reusable program-detail structure. Each program could retain distinct content while sharing typography, spacing, navigation, responsive behavior, and visual hierarchy.

Responsive Design

Designing for the Audience

Stakeholders indicated that approximately 60% of traffic came from mobile devices, so responsive behavior was a core requirement—not a final pass. Layouts, typography, navigation, cards, imagery, and interactive elements were tested and adjusted across viewports.

View responsive screenshots
Accessibility & Usability

Clarity Before Decoration

Accessibility and readability influenced typography, sizing, spacing, hierarchy, and responsive behavior. The goal was not simply to make JerseySTEM look newer; it was to make programs, impact, leadership, and opportunities easier to understand and navigate.

  • Readable typography
  • Clear hierarchy
  • Mobile legibility
  • Consistent calls to action
  • Responsive layouts
  • Predictable navigation

Outcomes

Reflection

What I Took Away

JerseySTEM pushed me beyond simply translating a design into code. The project required system-level thinking: reusable patterns, evolving requirements, development overhead, and the needs of people maintaining the website afterward.

It reinforced the connection between my UX foundation and UI Engineering work. Hierarchy, accessibility, and user behavior informed the design; frontend engineering turned those decisions into a working responsive experience.
